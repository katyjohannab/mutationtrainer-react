# Treiglap audit and refresher

Audit date: 26 September 2026. Snapshot: commit `e994aa5` plus the existing working-copy changes to the source/preset registries and tests, including the untracked `packRegistry.js`.

**Assessment:** the app has a useful foundation and a coherent visual identity, but its content and practice results are not yet dependable enough for a wider learner release. Repairing content validation, card identity, review state and admin persistence should come before adding more packs or redesigning the app.

This audit makes no changes to application code or teaching content. It adds documentation and local diagnostic artifacts. Existing user changes were preserved. The implementation sequence is in [the improvement plan](IMPROVEMENT_PLAN.md).

## How the app currently works

### For a learner

Treiglap displays a Welsh base word and a sentence with a gap. The learner supplies the form that belongs in the gap; sometimes the correct answer is the unchanged word. Type mode accepts text. Tap mode generates up to three options. Checking or revealing the answer replaces the question with the completed sentence, an explanation, an English translation when present, and a pronunciation control.

Random mode samples the current pool, trying to avoid recently graded/shuffled cards. It is not a shuffled deck that finishes after every card. Smart mode uses a simple Leitner schedule: successful reviews move a card through intervals of 10 minutes, 1 hour, 1 day, 3 days and 7 days; wrong/revealed reviews go back to immediate review. “Easy” can move a correct card two boxes. “Hard” maps to “again” and resets it. When nothing is due, Smart currently selects the earliest future card immediately rather than offering a completed-session screen.

The app starts with the entire registered pool and Welsh interface text. The sidebar on large screens, or Filters drawer on smaller screens, offers starter packs and custom filters. Selecting a pack clears advanced filters; selecting an advanced filter clears the pack. The current UI does not expose the course → dialect → unit journey described in the old documentation.

Language, audio autoplay, onboarding dismissal and the Leitner map are saved in this browser's local storage. Active pack, filters, answer mode, session accuracy and streak are not restored after reload. There are no user accounts, cross-device sync or learner-progress backups. “Reset session” resets visible session statistics, not the stored Leitner history.

### For you as maintainer

The source files in `public/data` are the teaching content. The loader reads the explicitly registered CSV/TSV files; it does not scan that folder automatically. It maps different header conventions into a common card shape. Answer checking compares against the stored answer, tolerating case and extra spaces. The mutation engine mostly supplies missing answers and generates Tap alternatives: **fixing the engine alone will not fix wrong answers already stored in the data.**

The main implementation areas are:

| Area | Files | Responsibility |
| --- | --- | --- |
| App/session | `src/App.jsx` | Loaded pool, filters, modes, current card, statistics, admin state |
| Practice UI | `src/components/PracticeCard*.jsx` | Question, choices, grading, reveal, keyboard handling |
| Content registration | `src/data/csvSources.js`, `packRegistry.js`, `dysguUnitRegistry.js` | Which files are loaded and how packs/units are described |
| Content loading | `src/services/loadCsv.js`, `csvFieldMap.js` | Parsing, field mapping, source metadata, fallback IDs |
| Learning logic | `src/utils/checkAnswer.js`, `grammar.js`, `leitner.js`, `pickNext.js` | Accepted text, generated forms, scheduling, selection |
| Language | `src/i18n/strings.js`, `I18nContext.jsx` | English/Welsh interface strings |
| Audio | `src/services/ttsPolly.js` | Sends completed sentence text to a configured or fallback AWS Lambda endpoint |
| Admin | `server/adminApi.js`, `viteAdminApiPlugin.js` | Password session and filesystem editing of CSV/TSV sources |
| Deployment | `.github/workflows/deploy.yml`, `scripts/start-prod.cjs` | GitHub Pages build/deploy; separate Vite-preview-based writable runtime |

`src/content-gen` is intentionally parked. Its more structured schema and QA machinery do not currently validate the live CSV pool. Keep it parked while repairing the active path.

Normal development is `npm install` once and `npm run dev`, then open the local URL Vite prints. Production build is `npm run build`. The current base-path default is `/`; the GitHub Pages workflow explicitly sets `/mutationtrainer-react/`. Older README URLs should not be assumed to match every local setup. Do not rely on production admin editing until findings A04–A05 are fixed.

## Scope and evidence

I inspected the active components, loader, registries, filters, grammar helpers, answer checking, review scheduler, bilingual copy, admin API, deployment configuration, tests and project documentation. I ran the existing test suite, build and verification scripts, scanned all loaded rows through the actual Vite-transformed runtime loader, and exercised the app in the browser in English and Welsh.

Browser coverage included onboarding, Type mode, feedback, keyboard Hint activation, custom filters, a one-card Smart session, repeated submission, mobile drawer and responsive layouts at 390×844, 320×568 and 1366×768. These are browser viewport checks, not tests on physical mobile devices or a full screen-reader certification. Tap options were evaluated across the complete loaded dataset.

Admin write tests used disposable copies under `output/audit-2026-09-26/admin-fixture`; no real content file was edited. The production-data test used the same preview/middleware arrangement with a minimal fixture.

Welsh checks used specific examples against the included *Mynediad y De, Fersiwn 2 (2023)* coursebook, especially pages 358–360 (visually inspected), plus [Aberystwyth University's mutation reference](https://users.aber.ac.uk/bmj/Tr/Cym/tr2.html) and [Welsh Government's BydTermCymru guide](https://www.gov.wales/bydtermcymru/style-guide). This is a targeted, evidence-backed language audit; it is not a claim that every sentence has been certified by a fluent Welsh teacher.

## Findings requiring repair before wider release

### A01 — Wrong Welsh is being accepted and taught (P1, confirmed)

There are **38 cards that change initial `ff` to `f`**: 4 in `cards.tsv`, 22 in `prep.csv`, and 12 in `article-sylfaen.csv`. Initial `ff` is not one of the consonants undergoing ordinary soft mutation. The engine correctly leaves `ff` alone, but the stored answer and explanation override that knowledge.

Examples:

| Card | Current content | Required review/correction |
| --- | --- | --- |
| `p000016` | `am ffôn` expects `fôn` | Keep `ffôn`; rewrite both explanations |
| `a000072` | Article + `ffafr` expects `fafr` | Keep `ffafr` |
| `c001367` | `yn fferyllydd` expects `feryllydd` | Keep `fferyllydd` |
| `c000212` | Base `papur`, answer `phen`, explanation discusses `pen` | Correct the mismatched card; for the displayed “her paper” context the form is `phapur` |
| `c000655` | Article + `llaw` expects `law` | The article's feminine-noun rule exempts initial `ll`/`rh`; use `llaw` in this context |
| `M-D-00403` | `Corwen` → `Ngorwen` after `yng` | Standard nasal transformation is `Nghorwen` |
| `M-D-00106` | `Bae Colwyn` → `Fae Colwn` | The answer drops an internal `y`; mutation should not do that |

The consonant patterns and the article exception are supported by the coursebook table and [Aberystwyth's reference](https://users.aber.ac.uk/bmj/Tr/Cym/tr2.html). The place pack also has mixed spellings such as `Caerfili`/`Gaerffili`/`Gaerfilli`, `Tyddewi`→`Dddewi`, English-name substitutions, and `Laugharne`→`Naugharne`. Review place names as whole lexical items, with an agreed Welsh naming policy; do not assume a first-letter transform validates them.

**Impact:** learners can be penalised for correct Welsh and rewarded for incorrect Welsh. This outranks visual polish.

### A02 — Malformed Unit 2 rows become live questions (P1, confirmed)

`Uwch1/unit2.csv` has **17 rows with too many fields**, principally unquoted commas. The loader logs warnings and loads them anyway. On five cards, sentence fragments become answers and actual answers become the `outcome` value.

For `U110064`, the parsed expected answer is `ac felly’n llai agored i bwysau gwleidyddol.` and its outcome is `annibynnol`. Other invalid outcomes are `gytbwys`, `gais`, `dant` and `berchen`. Unknown outcomes fall through to “None” in filtering, disguising the corruption.

The admin save path rejects a file with any parse errors, so Unit 2 cannot currently be repaired using its normal card editor. Correct the source with a CSV-aware editor, validate every row, and reject invalid live data at build/load boundaries.

Evidence: `src/services/loadCsv.js:158`, `src/utils/applyFilters.js`, `server/adminApi.js:397`, source file lines 2–18.

### A03 — Duplicate IDs mix progress between unrelated cards (P1, confirmed)

IDs `U110055` through `U110059` occur in **both Uwch units**. The scheduler keys progress only by `cardId`, so learning one sentence can affect the other. Reported IDs are ambiguous. The practice component resets only when the ID changes, which can also preserve stale feedback when changing between these different cards.

Assign globally unique stable IDs and introduce a deliberate progress migration. For the five ambiguous existing IDs, do not silently attribute old progress to both replacement cards.

Evidence: `src/utils/pickNext.js:6`, `src/components/PracticeCard.jsx:53–65`, Unit 1/2 records.

### A04 — Admin TSV saves alter unrelated content (P1, reproduced with fixture)

The TSV reader disables quote parsing with `quoteChar: "\0"`; the writer uses Papa Parse's default quoting. Saving a single translation in a copy of `cards.tsv` changed **90 unrelated cells across 65 other rows** when reread by the app's parser. Literal quotes become doubled/wrapped text. For example, an explanation containing `"eu"` gains quoting characters rather than round-tripping as the same value.

Unify TSV parsing/writing rules, validate the complete output before replacing the source, and prove that untouched cells remain identical. Do not use the current editor for bulk cleanup.

Evidence: `server/adminApi.js:386–438`; reproducible inspector and results under `output/audit-2026-09-26`.

### A05 — Production-style edits are not served after reload (P1, reproduced with fixture)

`start-prod.cjs` launches Vite preview, which serves built files from `dist`. The admin endpoint writes `public/data`. Its response updates the current React state, making a save look successful, but a new load still fetches `dist/data`.

The fixture test saved `gi` to the source while HTTP still returned the old `ci`. Establish one canonical runtime data location, serve edits from that location with appropriate cache behavior, and protect it from deployment overwrites. Add atomic writes, a backup/revision record and stale-edit detection; current direct whole-file writes also risk lost updates from overlapping saves.

This concerns the configured writable preview runtime. GitHub Pages is a separate static deployment and cannot run these filesystem admin endpoints.

### A06 — Review sessions can get stuck and count the same answer twice (P1, browser-reproduced)

Reproduction: choose advanced filters **Uwch → None → Determiner**. This gives one card, `U110006` (`ffefryn`). Select Smart, answer correctly and choose Next. It remains on CORRECT with Hard/Easy/Next disabled. The scheduler selected the same row, but the UI resets only on a different ID and `isSubmitting` remains true.

Pressing Enter again then increased the streak a second time. `recordResult` runs before the duplicate-review guard in `App.jsx`. In the observed session, one earlier wrong answer plus one correct answer should have produced 50% accuracy; the duplicate submission displayed **2 streak / 67% accuracy**.

Use an explicit presentation/review ID, reset for every presentation, and commit grading/statistics/scheduling as one idempotent event. Decide what happens when no card is due. Test one-card and two-card pools, immediate repeats, mode switches and duplicate submissions.

### A07 — Global shortcuts override other controls (P1, browser-reproduced)

Focusing Hint and pressing Enter marks the empty answer wrong instead of activating Hint. The window-level handler excludes text fields but not buttons, dialogs, switches, links or other interactive controls; it prevents their native Enter/Space behavior. The same design can interfere with filter/help/report flows.

Scope shortcuts to the practice surface, respect focused controls and open dialogs, and prevent grading blank submissions. Verify all important actions with keyboard-only navigation.

## Interface, accessibility and learning quality

### A08 — Course content is inaccessible through the expected selector (P2, confirmed)

The Uwch tab is disabled even though two registered units supply 124 cards. `DysguLevelPacks` uses `DYSGU_PACKS_BY_LEVEL`, which is built from `PACK_REGISTRY`, while the course units are placed separately in `PRESET_DEFS`. Thus loaded content, available presets and visible navigation disagree.

Unify the UI's view of approved course units and standalone packs. Keep unavailable North/Canolradd content visibly distinguishable from content that exists. Treat the unregistered 54-card Mynediad file as a review decision, not an automatic enablement task.

### A09 — Tap choices can be trivial or linguistically invalid (P2, confirmed)

Across the full pool, **528 cards produce only one unique choice**, so Tap gives the answer away. `mutateWord` handles `ll` and `rh` but otherwise looks at the first character: `chwarae` can produce `ghwarae` and `nghhwarae`. These are generated from a real loaded base word. Treat Welsh digraphs as single letters and use reviewed alternatives.

For words with no distinct legitimate mutation options, use a meaningful “change/no change” exercise or Type mode. Do not invent malformed alternatives to force three choices. The pipe-separated accepted-answer feature has a separate latent mismatch: Tap treats `a|b` as a single option while the checker expects either `a` or `b`. No live rows currently use pipes, so this is a future compatibility defect, not a current content count.

### A10 — Several controls are not accessible as controls (P2, confirmed)

Filter chips, reset chips and the report trigger use `Badge`, which renders a `div`, with click handlers instead of appropriate button/checkbox semantics. The browser accessibility tree exposes the custom filter choices as text. The answer input has no associated label or `aria-label`. Feedback has no explicit live region/focus transition. The HTML language remains `en` when the interface is Welsh, and Welsh exercises lack their own language annotation.

Replace actionable badges with native controls, expose selected state, provide a labelled answer field and an announced result, set the document language, and mark Welsh/English passages appropriately. Validate with a screen reader after the keyboard fix.

### A11 — The selected task is unclear, especially on mobile (P2, observed)

The UI has a recognisable brand and generally adapts without horizontal overflow in the checked viewports. However:

- The selected pack name is calculated and passed as `deckLabel`, but not rendered. A mobile learner sees a count and internal card ID without a clear session title.
- Desktop Help is hidden at the `xl` breakpoint. A returning user cannot reopen the guide there.
- The mobile drawer stays open after pack selection; an `onPresetApplied` callback is supplied by App but never consumed by FiltersPanel.
- The two independent Random/Smart and Type/Tap controls are not self-explanatory. Their selection and custom filters are lost on refresh.
- The generic “Type the mutated form” prompt implies a change is always required, even for 1,274 unchanged cards.
- Feedback does not show the learner's own attempted answer alongside the expected form.
- At 320×568, the main Check control lies below the initial fold. At laptop height, feedback actions can also require scrolling. This is a usability finding, not evidence of horizontal overflow or clipping.
- Session statistics disappear from the mobile feedback view, while reset is available only in the desktop stats rail.
- `Card N / pool size` counts views, not unique completed cards, and can exceed the denominator. “Reviewed” includes any saved entry, not mastery or today's completed reviews.

Prioritise a clear session title, a concise instruction, a stable primary action, useful feedback and a real completion state. Keep the dragon/colour palette and reduce competing surfaces and wasted vertical space rather than replacing the whole design.

### A12 — Bilingual parity and explanations need editorial review (P2, confirmed examples)

The dictionary has matching keys, but feedback hardcodes “Autoplay”, generic Radix close text is English, and some API/audio errors are raw English. The audio check displayed “Failed to fetch” in the Welsh interface; this establishes a failed request in the audit environment, not whether the underlying cause is network access, configuration or the service. Unit 2 contains Welsh text in the English `Why` field; a simple prefix scan identified 31 such candidates. Many general cards have no sentence translation. Some Welsh explanations include English fragments or point to the wrong trigger: e.g. place card `M-D-00021` uses `o` but its Welsh explanation says `i`.

There are also erroneous fallback rules in `src/data/rules.js`: `aspirate-conj-neu` calls `neu` aspirate, and `nasal-misc-recog` calls several aspirate triggers nasal. `none-general-yn` is overbroad because predicate nouns/adjectives differ from verb-nouns. **No currently loaded row has a rule ID, so these fallback texts are not the source of the live answer errors listed above.** Repair them before connecting content to them. The `neu` correction is also supported by [BydTermCymru](https://www.gov.wales/bydtermcymru/style-guide).

A bilingual reviewer should check complete sentences, answer/base alignment, noun gender, grammatical trigger, explanation accuracy, English meaning and dialect/register. Do not classify a valid dialect variant as a mistake simply because it differs from the preferred teaching form.

## Maintainability and operating risks

### A13 — There is no effective publication gate for content (P1 foundation work)

The live pool includes **115 Draft and 60 Generated cards**, 8 marked Fixed, and 3,316 without QA status. None are marked Checked. Missing status does not prove a card was never reviewed, but the app cannot establish that it was. The loader never filters by review status. The hidden `starter-all-verified` preset name also has no review-status enforcement.

The schema checks in the parked generator do not protect this path. Add one runtime content validator that parses every registered source and rejects malformed fields, duplicate IDs, invalid outcomes, missing required text and inconsistent metadata. A mechanical pass cannot replace language review: publication also needs reviewer/version/source information and an explicit approved state.

### A14 — Failures are silent and the release checks miss the important paths (P2)

If a source fetch fails, the loader returns an empty list and logs an error; other sources continue loading. The user cannot distinguish a partial deck from the intended deck. Initial loading and a genuinely empty filter result use the same no-cards presentation. All six data sources, about 1.4 MB before transfer compression, are eagerly loaded.

CI currently installs and builds before deploying. It does not run the tests, lint or content verification. There are no tests directly covering `checkAnswer`, Leitner scheduling, card selection or rendered learner interactions. The browser also reports invalid nested paragraph markup in WelcomeModal (`DialogDescription` renders a paragraph and contains paragraphs); fix that semantic markup. Add targeted regression tests for the reproduced failures first. Introduce lazy per-pack loading only after correctness and honest loading/error states are established.

### A15 — Deployment and support need one clear runbook (P2)

The repository supports a static GitHub Pages workflow and a separate writable runtime, but the latter uses a preview server and has the persistence defect above. Decide which model is intended for public learners and where editing happens. The current admin login has no application-level rate limit, and saves have no revision history or concurrency control. These are implementation gaps to address before exposing a writable service; this audit did not probe a public server or establish whether a reverse proxy supplies protections.

The mistake-report flow opens an email draft or GitHub issue composer; it does not itself send a report. Onboarding and the “Send report” label promise more than that. Make the handoff explicit and retain a copyable report if an email client is unavailable. Include source and content version so a report still identifies the exercise after repairs.

Audio uses an external endpoint, has no request timeout/cancellation, and retains generated object URLs without an eviction policy. This audit does not certify pronunciation quality; a Welsh speaker should assess it against the intended dialect. Record endpoint ownership/configuration and a support/failure path before launch.

### A16 — Documentation and visual defaults lag behind the app (P3)

The README/architecture/handoff describe course → dialect → unit controls that are no longer in the UI. `.github/copilot-instructions.md` still directs new content into the parked generator. “Freshness” checks pass despite these disagreements. The page title and favicon remain Vite defaults. Update the human quickstart, contributor instructions and deployment matrix together after choosing the active workflow.

## What to retain

Explicit source registration, shared header mapping, source/row provenance, the admin source allowlist, bilingual string dictionaries, simple filter functions and the existing unit tests are worth keeping. The main question/feedback components are already separated enough for targeted repairs. The current visual identity is recognisable. A new framework, database, account system or full rewrite is not required to address the confirmed defects.

## Evidence artifacts and limitations

Local diagnostics are in `output/audit-2026-09-26/`:

- `content-summary.json`: counts from the actual runtime loader.
- `content-findings.json`: duplicate IDs, mutation-helper disagreements and other candidate lists. Record positions are not physical source line numbers; use card IDs and source filenames.
- `runtime-rows.json`: normalised pool used for the scan.
- `inspect-content.mjs`: read-only diagnostic; regenerate with `node output/audit-2026-09-26/inspect-content.mjs`.
- `admin-findings.json`, `inspect-admin.mjs`: reproducible disposable-fixture checks for TSV and production-data persistence.
- `eslint.json`: the lint findings captured before audit artifacts were added.

The report distinguishes browser/fixture reproductions, source-code findings and language-review candidates. Not covered: a complete tutor sign-off of all 3,499 cards; physical-device/audio-pronunciation assessment; live hosting/proxy/backups; load testing; a full assistive-technology audit; or npm's blocked external advisory scan. These should be explicit release work, not treated as passed checks.
